# Model Card: логистическая регрессия для классификации табличных данных

> **Проект:** ML Project Demo
> **Статус:** учебный прототип; обученная модель и подтверждённые результаты экспериментов в репозитории отсутствуют.
> **Дата документа:** 13.10.2026
> **Формат:** разделы Model Card по подходу Google / Mitchell et al. (2019).

## 1. Сведения о модели (Model Details)

| Поле | Описание |
| --- | --- |
| Название | Logistic Regression — классификатор табличных данных |
| Задача | Обучение с учителем: классификация объектов по признакам |
| Алгоритм | `sklearn.linear_model.LogisticRegression` |
| Тип результата | Дискретная метка класса; бинарная или многоклассовая классификация в зависимости от целевой переменной |
| Версия кода проекта | `0.1.0` (`pyproject.toml`); версия обученного артефакта не определена |
| Реализация | [`src/models/trainer.py`](src/models/trainer.py) |
| Параметры обучения | `max_iter=1000` задан непосредственно в функции обучения; прочие параметры — значения scikit-learn по умолчанию |
| Библиотека | scikit-learn (допустимая версия по `pyproject.toml`: `>=1.9.1,<2.0.0`) |
| Лицензия модели / проекта | Не указана в репозитории |

**Назначение в проекте.** Модель выступает базовым ML-компонентом учебного конвейера: на размеченных табличных данных изучает зависимость между характеристиками объекта и его классом, предсказывает класс для тестовых наблюдений и позволяет оценить качество по `accuracy`.

**Предметная область пока не определена.** В репозитории не заданы бизнес-сущность, список признаков, название целевого столбца и смысл меток. Поэтому нельзя достоверно утверждать, что модель, например, выявляет мошенничество, прогнозирует отток или оценивает кредиты. Конкретный сценарий необходимо указать после выбора датасета.

## 2. Предполагаемое использование (Intended Uses)

**Основное использование:** учебные эксперименты по классификации структурированных записей, сравнение предсказаний с истинными метками и проверка базового качества модели перед дальнейшим развитием проекта.

**Пользователи:** разработчик / ML-специалист, который готовит данные, запускает обучение и анализирует результаты. Автоматический сервис для конечных пользователей в коде пока отсутствует.

**Почему ML:** когда правила отнесения записи к классу зависят от сочетания нескольких признаков, модель может извлекать закономерность из размеченных примеров. Логистическая регрессия подходит как простой интерпретируемый базовый алгоритм, с которым можно сравнивать более сложные решения. Преимущество перед фиксированными правилами в этом проекте пока не доказано экспериментально.

**Не предназначена для:** автономного принятия медицинских, финансовых, кадровых и иных значимых решений; обработки неструктурированных документов или изображений; прогнозов по данным другого формата без повторной проверки. Продуктовое внедрение не реализовано.

## 3. Входные и выходные данные

| Этап | Вход | Выход |
| --- | --- | --- |
| Загрузка | Путь к CSV (по конфигурации — `data/train.csv`, файл в архиве отсутствует) | `pd.DataFrame` через `load_csv()` |
| Предобработка | `pd.DataFrame`; для `fill_missing()` поддерживаются числовые столбцы | Копия таблицы с числовыми пропусками, заполненными средним, медианой или нулём |
| Обучение | `x_train: pd.DataFrame`, `y_train: pd.Series` | Обученный объект `LogisticRegression` |
| Оценка | `x_test: pd.DataFrame`, `y_test: pd.Series` | Предсказанные метки `model.predict(x_test)` и `accuracy` |
| Возврат функции | Результат обучения и проверки | `TrainResult(model: LogisticRegression, accuracy: float)` |

Функция обучения имеет сигнатуру:

```python
train_logistic_regression(x_train, y_train, x_test, y_test) -> TrainResult
```

**Требования к данным:** строки `X` и `y` должны соответствовать друг другу; обучающая и тестовая таблицы должны иметь совместимые названия и порядок признаков; значения должны быть числовыми и пригодными для `LogisticRegression` (категориальные признаки предварительно кодируются). Целевая переменная должна содержать как минимум два класса в обучающем наборе. Конкретные столбцы и их размерности пока не зафиксированы.

**Важно о пропусках:** [`fill_missing()`](src/features/transformer.py) работает только с числовыми колонками. В текущем проекте нет единого конвейера `Pipeline`, который запоминает параметры обработки исключительно по обучающей выборке. Для корректной оценки необходимо подбирать параметры импутации на `train` и применять те же параметры к `test` и новым данным, исключив целевой столбец из обработки признаков.

## 4. Существенные факторы (Factors)

На качество предположительно влияют доля пропусков, масштаб признаков, соотношение классов, выбросы, изменения состава данных во времени и наличие категориальных полей. Поскольку предметная область не определена, доменные и демографические подгруппы для отдельного анализа пока не установлены.

При наличии соответствующих данных следует оценивать качество не только в среднем, но и по значимым группам объектов и условиям сбора данных, соблюдая требования приватности.

## 5. Метрики качества (Metrics)

**Реализованная метрика — Accuracy:**

$$
\mathrm{Accuracy}=\frac{\text{число верных предсказаний}}{\text{число всех тестовых объектов}}.
$$

В [`src/models/trainer.py`](src/models/trainer.py) после `model.fit(...)` выполняется `model.predict(x_test)`, затем `accuracy_score(y_test, predictions)`. Метрика возвращается в `TrainResult.accuracy`.

**Планируемые дополнения:** `precision`, `recall`, `F1` по классам, матрица ошибок; для бинарной классификации при наличии вероятностей и соответствующей задачи — `ROC-AUC` и/или `PR-AUC`. При дисбалансе классов одной `accuracy` недостаточно. Полезно сравнить результат с простым базовым правилом (например, предсказывать наиболее частый класс).

**Порог решения:** явная настройка порога в проекте отсутствует. Функция использует стандартное правило `predict()` из scikit-learn. Допустимый уровень качества для запуска в эксплуатацию не установлен.

## 6. Данные для оценки (Evaluation Data)

Функция ожидает независимый набор `x_test`, `y_test`, переданный вызывающим кодом. В репозитории **нет тестового датасета**, процедуры разбиения, описания метода формирования выборки и сведений о распределении классов. Следовательно, независимость тестовой выборки и отсутствие пересечений с обучением не подтверждены.

Для воспроизводимой оценки следует документировать источник данных, период наблюдения, объём, распределение целевого признака, схему `train/test` (а при подборе параметров — и `validation`), способ устранения дубликатов и случаи возможной утечки информации.

## 7. Данные для обучения (Training Data)

В [`configs/config.yaml`](configs/config.yaml) указан предполагаемый путь `data/train.csv`, но CSV-файл не включён в проект. Источник, лицензия, число объектов, перечень признаков, баланс классов и качество разметки **неизвестны**. В коде нет встроенного механизма получения или разметки данных.

Реализованы отдельные подготовительные функции: загрузка CSV в [`src/data/loader.py`](src/data/loader.py) и заполнение числовых пропусков в [`src/features/transformer.py`](src/features/transformer.py). Подготовка признаков, кодирование категорий и разделение на выборки остаются задачами вызывающего кода.

## 9. Этические вопросы (Ethical Considerations)

- **Смещение данных.** При неравномерной представленности объектов модель может систематически ошибаться на редких группах; степень риска пока неизвестна.
- **Конфиденциальность.** Не собирать и не публиковать персональные данные без правового основания; при появлении чувствительных признаков ограничить доступ и документировать их использование.
- **Влияние ошибок.** Ложные срабатывания и пропуски могут иметь разную стоимость. До выбора предметной области такая стоимость не оценена.
- **Ответственность.** Для значимых решений необходимы контроль человеком, проверка качества и возможность оспаривания, а не слепое применение `predict()`.

## 10. Ограничения и рекомендации (Caveats and Recommendations)

1. **Стадия разработки:** есть функция обучения и тест для заполнения пропусков, но нет датасета, исполняемого end-to-end сценария, сохранённого артефакта, API, мониторинга или развёртывания.
2. **Конфигурация не полностью подключена:** `model.max_iter: 1000` в YAML совпадает с кодом, но фактически параметр жёстко задан в `trainer.py`; `model.random_state: 42` в файле конфигурации не передаётся в `LogisticRegression`. Аналогично `data.strategy: mean` не применяется автоматически.
3. **Предобработка может привести к утечке:** раздельное вычисление средних на тесте или обработка всего датасета до разделения даст некорректную схему эксперимента. Рекомендуется `sklearn.pipeline.Pipeline` с `SimpleImputer`, обучаемым на тренировочных данных.
4. **Область применимости ограничена:** логистическая регрессия без дополнительной подготовки не работает с произвольными строками, изображениями и нечисловыми полями; чувствительна к представлению признаков и качеству разметки.
5. **До реального использования:** определить бизнес-задачу и целевую переменную; добавить датасет или инструкции получения; реализовать воспроизводимое разделение и единый preprocessing pipeline; рассчитать метрики и их разбивку; зафиксировать версии модели и данных; определить критерии приёмки и способ использования предсказаний.
